# Synthetic Data

Synthetic data is data generated by a model or a program rather than collected from the world. Teams use it to create training examples where real data is scarce, expensive or private, and to shape what a model learns. Its value depends on quality control: generated data can teach a model well, but it can also copy the generator's biases and, when repeated across generations, erode the distribution the model learns from.

## Overview

Real data is limited. High-quality human text is finite, many tasks need labels no one has written down, and some data cannot be shared. Synthetic data fills these gaps. A strong model can write instruction-response pairs, reasoning traces, stories or code tests that a smaller model then learns from, or that are used to evaluate a system. The central question is whether the synthetic examples add information the model did not already have, or only repeat what the generator already knew.

## Key concepts

- **Distillation-style generation**: a stronger teacher model writes data for a weaker student. Most instruction-tuning datasets are built this way.
- **Self-generated data**: a model bootstraps its own training examples, often with filtering, which can work but depends on the quality of the seed set.
- **Programmatic synthesis**: templates, simulators and rule-based generators produce examples with known labels, useful for robotics, driving and tabular data.
- **Quality filtering**: classifiers, execution checks for code, answer verification for maths, and deduplication remove weak examples before training.
- **Diversity**: many synthetic datasets are narrow. Generators are prompted with varied topics, personas or seeds to avoid repeating a single style.
- **Model collapse**: training on the outputs of earlier models, generation after generation, can remove rare parts of the original distribution.

## How it works

A typical pipeline has four stages, each with its own failure modes:

```mermaid
flowchart LR
  S[Seeds and topics] --> G[Generate with a model or program]
  G --> F[Filter: quality, correctness, dedup]
  F --> M[Mix with real data]
  M --> T[Train and evaluate on held-out real data]
  T -. feedback .-> S
```

The last step matters most. Synthetic training data should be checked on real, held-out tasks, since a model can score well on its own synthetic examples while failing on real ones. The mix ratio between real and synthetic data is a design choice, not a constant.

## Key methods

### Self-Instruct (Wang et al., 2023)

- **Problem:** instruction tuning needed large sets of human-written instructions, which were slow and expensive to collect.
- **Core idea:** start from a small seed set of instructions written by people, prompt a language model to write new instructions and matching inputs and outputs, filter out near-duplicates and low-quality items, and use the rest to fine-tune the model.
- **Equation or algorithm:** an iterative loop. Sample seed and generated tasks, prompt the model for new instructions in the same format, classify whether each needs an input, generate the output, then discard candidates whose ROUGE-L similarity to existing tasks is above a threshold.
- **Results:** the paper reports that instruction tuning on the generated data gives a large improvement over the base model, without a large human-written instruction set.
- **Limitations:** the generated data reflects the generator's style and errors. Later work, such as Alpaca-style datasets, showed that quality checks matter as much as quantity.

### Textbooks Are All You Need (Gunasekar et al., 2023)

- **Problem:** whether a small model could match much larger models on code if it learned from better data, rather than from more data.
- **Core idea:** train a small model on a filtered subset of web code and on synthetic "textbook-quality" text and exercises generated by a larger model. The data is chosen for educational value and clarity rather than volume.
- **Equation or algorithm:** no single formula; the method is a data-selection pipeline. Filter web data with a quality classifier, generate textbook and exercise content with prompts that ask for clear explanations, and then pre-train on the combined corpus.
- **Results:** the paper reports that a 1.3-billion-parameter model trained on a few billion tokens of this data achieves strong code generation results for its size.
- **Limitations:** the benchmark results depend on how close the synthetic exercises are to the evaluation tasks. Later work asks how much of the gain comes from benchmark overlap.

### TinyStories (Eldan and Li, 2023)

- **Problem:** whether language models need very large scale to produce coherent text, or whether the training data's simplicity matters more.
- **Core idea:** generate a dataset of short stories written in the vocabulary a young child would understand, using a large model. Train very small models on this dataset, showing that coherent, grammatical English can emerge at a small scale when the data is well chosen.
- **Equation or algorithm:** no formula; the method is controlled data generation, with prompts that specify vocabulary and story structure, followed by standard language-model training.
- **Results:** the paper reports that models with only a few million to tens of millions of parameters produce fluent, consistent stories on this data.
- **Limitations:** the domain is narrow and the outputs are simple. Results on general knowledge tasks are not the point of the study.

### Model collapse (Shumailov et al., 2024)

- **Problem:** if each new model is trained on web data that increasingly contains earlier models' output, the quality of later models might degrade.
- **Core idea:** train a model on data sampled from the previous model, repeat over generations, and measure what is lost. The authors show that the tails of the original distribution disappear first, and that performance on rare events falls sharply.
- **Equation or algorithm:** the procedure is a generational loop. For generation $k$, fit a model to samples drawn from the model of generation $k-1$; the paper analyses how estimation error accumulates in this loop.
- **Results:** the paper reports collapse across language models, variational autoencoders and Gaussian mixture models, with the loss of rare content appearing early and gaining speed over generations.
- **Limitations:** collapse depends on how the data is mixed. Keeping a share of the original real data, or accumulating data across generations, reduces the effect in the paper's experiments.

## Applications

- **Instruction and chat tuning**: most open instruction datasets are partly or wholly generated by a model.
- **Code and maths**: solutions can be checked by running tests or verifying answers, which makes filtering reliable.
- **Robotics and autonomous driving**: simulators generate rare scenarios that are hard to collect on the road.
- **Privacy-preserving analytics**: synthetic records can mimic the statistics of a dataset without exposing individuals, though this needs formal checks.

## Open questions

- **Usefulness versus novelty**: how much of what a model learns from synthetic data is new, rather than a restatement of the generator's knowledge?
- **Measuring quality**: filters and classifiers are themselves models with biases, so quality control can inherit the problems it aims to fix.
- **Contamination**: synthetic data built from benchmark-like sources can inflate scores.
- **Recursive training**: how much real data is needed to prevent collapse at scale is still debated, and depends on how the data is mixed and filtered.

## References

### Seminal papers

- Wang, Y. et al. (2023). *Self-Instruct: Aligning Language Models with Self-Generated Instructions*. ACL 2023. https://arxiv.org/abs/2212.10560 — Shows that a model can bootstrap instruction-tuning data from a small human-written seed set.
- Gunasekar, S. et al. (2023). *Textbooks Are All You Need*. https://arxiv.org/abs/2306.11644 — Trains a small code model on filtered web data and synthetic textbook-style content, arguing that data quality can substitute for scale.
- Eldan, R. & Li, Y. (2023). *TinyStories: How Small Can Language Models Be and Still Speak Coherent English?* https://arxiv.org/abs/2305.07759 — Generates a controlled dataset of simple stories to show that small models can produce coherent text.
- Shumailov, I. et al. (2024). *AI models collapse when trained on recursively generated data*. Nature, 631. https://doi.org/10.1038/s41586-024-07566-y — Shows that recursive training on model-generated data loses the rare content of the original distribution.

### Surveys

- Liu, Z. et al. (2024). *Best Practices and Lessons Learned on Synthetic Data*. https://arxiv.org/abs/2404.07503 — Reviews generation, filtering and evaluation practices for synthetic data used to train language models.

# 提示工程

提示是向基礎模型描述任務的方式。隨著模型進步，這門技藝已從「神奇咒語」轉向**清楚溝通**與**脈絡工程**——提供正確的資訊、工具與範例。

## 核心原則

1. **明確說明目標、對象與格式。** 說清楚成功的樣子。
2. **提供脈絡**：為什麼這項任務重要、有哪些限制、相關背景文件。
3. **在格式或風格重要時展示範例**（少樣本）；變換範例以免過度模仿。
4. **結構化提示**：把指令、脈絡與輸入分開（使用標題或類 XML 標籤）。
5. **任務需要時要求推理**，或改用推理模型。
6. **指定輸出結構**（JSON schema、段落結構），並在可用時使用結構化輸出功能。
7. **以評估集反覆改進**，而不是只憑眼睛檢視一個範例。

## 技巧

| 技巧 | 說明 | 適用時機 |
|---|---|---|
| 零樣本指令 | 直接描述任務 | 強大的模型、簡單任務 |
| 少樣本 | 附上輸入—輸出範例 | 控制格式／風格、分類 |
| 角色／系統提示 | 設定人設、規則與脈絡 | 助理與產品 |
| 思維鏈 | 「一步一步想」或展示推理過程 | 非推理模型處理數學、邏輯與多步驟問題 |
| 自我一致性 | 取樣多條推理路徑後投票 | 以較高成本換取較高準確度 |
| 任務分解／提示鏈 | 拆成子任務，分別呼叫 | 複雜的工作流程 |
| ReAct／工具使用 | 推理與工具呼叫交錯進行 | 代理人 |
| 檢索增強 | 插入相關文件 | 知識密集型任務（[RAG](../rag/index.md)） |
| 自我批判／反思 | 要求模型審閱並修改 | 寫作、程式碼 |
| 提示最佳化 | 自動搜尋提示（DSPy、APE） | 有大量範例與可用的指標時 |

## 代理人的脈絡工程

- 系統提示保持聚焦；把穩定的內容放在前面，以利用**提示快取**
- 為工具提供清楚的名稱、說明與範例
- 管理長脈絡：摘要、按需檢索，並把最重要的資訊放在開頭或結尾（「迷失在中間」）
- 長任務的筆記與計畫寫入檔案保存

## 安全性：提示注入

脈絡中任何不受信任的文字（網頁、電子郵件、文件、工具輸出）都可能夾帶指令。應把它當作資料處理：清楚地與指令分隔、限制代理人的權限，並對重大動作要求確認。見[資訊安全](../../applications/cybersecurity/index.md)。

## 常見錯誤

- 模糊的要求（「讓它更好」）
- 互相矛盾的指令
- 範例與真實輸入的分布不符
- 要求模型知道它不可能知道的事（私有或非常新的事實），卻沒有提供資訊
- 充滿無關規則、過長的提示

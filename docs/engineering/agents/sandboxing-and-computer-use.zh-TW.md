# 沙箱與電腦操作代理

電腦操作代理（computer-use agent）會像人一樣操作軟體：讀取畫面，並送出點擊、按鍵與捲動。沙箱（sandboxing）則限制這類代理能觸及的範圍，使一次錯誤或一次攻擊無法擴散到任務之外。

本頁是[代理工程](index.zh-TW.md)的一部分。

## 概述

許多任務沒有 API。電腦操作代理仍能處理這些任務，方法是觀察畫面，並透過人會使用的同一種輸入裝置行動。同樣的能力也意味著，代理可能讀取私人檔案、傳送訊息並更改設定。沙箱就是讓這些能力保持在任務範圍內的一組控制。

## 關鍵概念

- **電腦操作迴圈：**代理觀察截圖或無障礙樹狀結構，模型選擇一個行動，執行該行動，然後觀察新的狀態。
- **沙箱：**隔離的執行環境，通常是容器或虛擬機器，擁有自己的檔案系統與程序。
- **最小權限：**只授予任務所需的檔案、帳號與網路存取。
- **出站允許清單：**沙箱可以連線的網路目的地清單。
- **限定範圍的短期憑證：**只適用於單一任務、並在短時間內過期的存取權杖。
- **確認步驟：**在不可逆的行動（例如付款或刪除）之前，由人類核准。

## 運作方式

典型的部署會結合數個層次。代理在虛擬機器或容器中執行，使當機或惡意行動只影響該執行個體。它的檔案系統限於工作目錄，網路存取則經過允許清單。憑證為該次工作階段發出，之後撤銷。每個行動與截圖都會被記錄，讓審查者能重建發生的事，並有一個可以停止執行的緊急開關。

透過畫面控制也很慢，且容易出錯。版面的小變化、彈出視窗與意外的對話框，都可能使代理偏離方向，因此迴圈通常會在採取下一步之前檢查每個行動的結果。

## 威脅模型與信任邊界

設計時首先要決定的不是哪個模型控制桌面，而是**誰有權執行哪些操作**。使用者提出目標、模型建議動作、獨立的政策執行器判斷是否允許執行。網頁、程式庫或截圖中的文字是任務資料，不是授權來源。Greshake 等人的研究說明，攻擊者控制的外部內容可能誘導整合 LLM 的應用程式呼叫非預期工具。

威脅模型至少應區分四類資產：**機密性**（文件、憑證與瀏覽器狀態）、**完整性**（檔案、訊息與帳號設定）、**可用性**（運算時間、速率限制與流量）及**稽核證據**。威脅來源則包含惡意遠端內容、遭入侵的工具或擴充功能、權限過大的代理，以及一般模型或介面操作失誤。單純要求模型忽略惡意指令，並不等同作業系統的存取控制。

例如代理的合法任務是下載公開發票並擷取金額，網站卻顯示偽造指令，要求上傳本機密碼資料。即使模型嘗試照做，執行器也應使上傳不可行：不掛載密碼資料、封鎖未核准的對外目的地、拒絕不在允許清單內的上傳操作。記錄違規嘗試有助於事後調查，但紀錄本身無法阻止外洩。

## 隔離方式與剩餘風險

| 邊界 | 隔離範圍 | 仍須注意的風險 |
|---|---|---|
| 獨立瀏覽器設定檔 | Cookie、歷史紀錄與瀏覽器偏好 | 其他工具仍可能存取主機檔案與網路 |
| 限制掛載的非 root 容器 | 程序與選定的檔案系統視圖 | 共用核心、過寬的掛載範圍與繼承的秘密 |
| 用完即丟的虛擬機器 | 客體作業系統與程序樹 | Hypervisor 漏洞、主機整合及已授權的網路出口 |
| 任務專用遠端服務 | 只開放狹窄 API 能力，不給完整桌面 | 服務端授權錯誤及過寬的 API scope |

這些是工程設計模式，不代表相同的安全保證。容器不會自動成為安全沙箱；虛擬機器也無法阻止經過授權管道的資料外洩。隔離必須搭配身分、授權及出站控制。若工作只需讀取單一文件，狹窄的唯讀 API 通常比完整桌面權限合適。

## 關鍵方法

- **能力範圍限制：**每次任務只核發必要的操作、路徑與短期憑證，執行前拒絕超出範圍的請求。
- **一次性環境：**每次從已知映像啟動，結束後重置可變狀態；這可減少跨次污染，但無法撤銷已發生的外部副作用。
- **人工核准交易：**在付款、傳送或刪除前，向人員顯示確切收件者、金額、目的地或目標。
- **狀態驗證互動：**每次點擊或命令後，檢查實際應用狀態是否符合預期，而非直接假設成功。

上述方法解決不同失效模式，實務上可同時採用。這些是實作控制方式，而非個別命名的研究演算法；代理基準及其方法另見[代理評估](agent-evaluation.zh-TW.md)。

## 可操作的執行流程

1. **準備：**建立全新環境，明列可掛載路徑、允許的網路目的地、帳號權限、步數與時間上限，以及緊急停止管道。
2. **觀察：**擷取畫面或無障礙樹，確認目前應用程式，並將外部內容標記為不受信任的觀察資料。
3. **提案：**讓模型以結構化格式提出動作、參數與預期結果；模型的理由不能直接當作授權。
4. **授權：**交由獨立政策檢查。高影響操作應針對具體參數取得人工確認，而不是事先概括核准整段工作階段。
5. **執行與驗證：**執行核准動作，觀察新狀態；遇到非預期對話框、目標變動或不明確結果時停止或復原。
6. **記錄與清理：**保存最少必要的時間戳記、工具參數、政策決策及遮罩後的證據；撤銷憑證並銷毀暫存環境。

GUI 自動化尤其要處理**檢查與使用之間的時間差**（TOCTOU）。從觀察按鈕到實際點擊期間，收件者或目標欄位可能改變。高影響操作前應重新確認目標，操作後再檢查伺服器端狀態。重試也不一定安全：傳訊息或轉帳可能產生重複的外部副作用，必須區分唯讀操作與非冪等操作。

## 不只看任務成功率的評估

OSWorld 與 WebArena 衡量代理是否達到指定終態，但成功率本身無法證明代理遵守授權。OSWorld 發表時包含 369 項跨桌面與網頁應用的任務；WebArena 則使用四個領域的可重現網站。原論文的基準成績只對特定模型與實驗設定成立，不應視為現今模型能力的固定上限。

部署評估應同時報告**任務成功率、違規操作嘗試次數、實際未授權副作用、人工介入率、錯誤復原率、執行延遲**及**每個成功任務的成本**。測試應在合法任務中加入惡意網頁、文件或工具回應，並檢查執行器是否真的擋下不允許的工具操作，而不只是模型是否口頭拒絕。乾淨與對抗性案例都要測試，以觀察安全性與任務完成率之間的取捨。

證據保存本身也是隱私決策。截圖可能包含個資或工作階段權杖；軌跡應限制存取、盡可能遮罩敏感資訊，並只保留除錯或問責所需的期間。

## 評估電腦操作代理

OSWorld（Xie 等人，2024）提供真實的電腦環境，讓多模態代理嘗試開放式任務，而不是侷限於單一應用程式的任務。WebArena（Zhou 等人，2023）則為網頁代理提供四個領域中寫實且可重現的網站。兩者都用來衡量代理能否完成任務，也顯示目前的代理距離可靠使用還有多遠。見[代理評估](agent-evaluation.zh-TW.md)。

## 安全

畫面內容是不受信任的。代理所看到的網頁、電子郵件或文件，可能含有代理可能遵循的指令，這就是 Greshake 等人（2023）所描述的間接提示注入風險。模型上下文協定（MCP）規範對工具也提出相同原則：使用者必須理解並同意工具會做什麼，主機在呼叫工具前必須取得明確同意（見[工具呼叫與 MCP](tool-calling-and-mcp.zh-TW.md)）。

實務上的防禦包括限制代理的權限、在提示中把指令與被觀察的內容分開、對不可逆行動要求確認，以及監控執行過程（見[LLM 應用安全](../llm-security/index.zh-TW.md)）。

## 限制

- **基準只涵蓋部分的真實使用。**基準環境是它所模擬軟體的簡化副本。
- **沙箱可能不完善。**沙箱本身的缺陷，或權限授予過寬，都會使保護失效。
- **感知錯誤。**代理可能誤讀畫面，尤其是小字或密集文字。
- **成本與延遲。**每一步都需要一次模型呼叫與一張新的截圖。

## 應用

- **軟體測試**：透過使用者介面執行腳本化流程。
- **在沒有 API 的舊系統中填寫表單**。
- **無障礙輔助**：代理代表有動作或視覺障礙的使用者操作介面。OSWorld 的作者即以無障礙與生產力作為這類代理的動機。

## 開放問題

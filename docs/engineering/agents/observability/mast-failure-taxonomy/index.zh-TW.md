# MAST：多代理人系統的失敗分類法

MAST（Multi-Agent System Failure Taxonomy，多代理人系統失敗分類法）是一份包含十四種失敗模式的清單，這些模式分為三個類別，用來解釋多代理人 LLM 系統為何會在任務中失敗。Cemri 等人（2025）以標註過的執行追蹤紀錄建立此分類法，並配上一個 LLM 標註器，用來為新的追蹤紀錄加上標籤。它是[代理人可觀測性與追蹤](../index.md)頁面中的關鍵方法之一。

## 概述

多代理人系統會賦予數個語言模型代理人不同的角色，例如規劃者、程式撰寫者與審查者，並讓它們相互對話以完成任務。它們相對於單一代理人的優勢往往不大。Cemri 等人報告，在七個開源系統中，失敗率從 41% 到 86.7% 不等。[^1]在團隊能修正這些失敗之前，必須先為它們命名；而過去的失敗報告多半是臨時性的，例如「代理人搞混了」，無法在不同系統之間相互比較。

MAST 提供了一套共通的詞彙：一組有定義的失敗模式，每個模式都有範例說明，標註者可以套用於任何追蹤紀錄。在此，失敗指的是系統未能達成其預期目標的一次執行。

## 關鍵概念

- **執行追蹤（execution trace）**：一次執行的完整文字，包括代理人之間的每則訊息與每個工具結果。作者的追蹤紀錄平均超過 15,000 行，因此人工標註十分緩慢。
- **失敗模式（failure mode）**：執行出錯的一種有名稱、有定義的方式，例如步驟重複（1.3）、過早終止（3.1）或推理與行動不一致（2.6）。
- **類別（category）**：*系統設計問題*涵蓋角色、歷史與終止條件如何被規定。*代理人間的失準*涵蓋代理人如何互動，例如扣留資訊。*任務驗證*涵蓋結果如何被檢查，或檢查得太少，或檢查錯誤。
- **扎根理論（grounded theory）**：用來推導此分類法的質性方法。類別是從對資料的細讀中浮現的，而不是事先固定的清單。
- **科恩 κ（Cohen's κ）**：兩位標註者之間的一致性統計量，會扣除偶然一致的部分：$\kappa = (p_o - p_e)/(1 - p_e)$。

## 運作方式

此方法分為七個步驟。

1. **蒐集追蹤紀錄。** 在常見的多代理人框架上執行程式撰寫、數學與一般代理人任務，並保留完整紀錄。
2. **開放編碼。** 由六位專家標註者分析來自五個開源框架的一百五十多條追蹤紀錄。
3. **一致性檢查。** 三位標註者各自獨立標註 15 條追蹤紀錄，然後修訂定義，直到 κ 達到 0.88。
4. **分類法。** 結果是三個類別共十四種失敗模式，每種都有定義與範例。
5. **LLM 標註器。** 一個推理模型（OpenAI 的 o1）接收追蹤紀錄、MAST 定義與少樣本範例，並回傳其中發現的失敗模式。
6. **驗證。** 將標註器與保留下來的人工標籤相比較，再於兩個框架與兩個基準上測試；這些框架與基準未曾用於建立分類法。
7. **規模化標註。** 通過驗證的標註器為完整資料集加上標籤，作者將其釋出為 MAST-Data。

此方法的核心在於標註程序，以及用來檢查每個定義是否清楚到足以被一致套用的一致性測試。

## 結果

主要證據是標註過的資料集與一致性數字，而非基準分數。

- **資料集。** MAST-Data 包含來自七個框架的 1,642 條標註追蹤紀錄，執行時使用 GPT-4 系列與 Claude 系列模型。
- **一致性。** 人工標註者在建立分類法時達到 κ = 0.88；在來自另外兩個系統與基準的追蹤紀錄上，則為 κ = 0.79。
- **LLM 標註器。** 在有少樣本範例的情況下，o1 在保留的人工標籤上達到 94% 的準確率，κ = 0.77。沒有範例時，準確率為 89%，κ = 0.58。[^2]
- **介入措施。** 在一個 ChatDev 案例中，讓 CEO 代理人擁有最終決定權，使任務成功率提高 9.4%。在一個 32 項任務的 ChatDev 基準上，改進的提示將準確率從 25.0% 提高到 34.4%，而重新設計的拓撲則提高到 40.6%。在使用 GPT-4 的 AG2 案例中，改進的提示有顯著助益，但拓撲的改動沒有（Wilcoxon p = 0.4）。[^2]

## 限制

- **涵蓋範圍。** 作者並未主張此分類法涵蓋所有失敗型態。
- **依賴標註器。** 規模化標籤來自單一推理模型，而該模型在沒有範例時的一致性遠低於有範例時，因此標籤取決於提示與模型的選擇。
- **只是部分修正。** 案例研究中的改動確有助益，但並非所有失敗模式都獲得解決。
- **標籤不等於原因。** 標籤說明出了什麼問題，但不說明是哪個代理人或步驟造成的。同一個模式也可能出現在管線的多個階段。

## 開放問題

- 此分類法能否推廣到其他系統、任務與之後的模型？
- 標籤能否支援因果歸因？Zhang 等人（2025）發現，自動評審找出負責代理人的次數遠多於找出決定性錯誤步驟的次數。其最佳方法的代理人層級準確率為 53.5%，步驟層級為 14.2%。[^3]
- 何時修改工作流程會比修改提示更有效？這兩個案例研究指向不同的方向。

## 參考文獻

### 奠基性論文

- Cemri, M. 等人（2025）。*Why Do Multi-Agent LLM Systems Fail?*。arXiv。https://arxiv.org/abs/2503.13657 — 提出 MAST 與 MAST-Data，包含來自七個多代理人框架的 1,642 條標註追蹤紀錄，以及一個 LLM 標註器。
- Zhang, S. 等人（2025）。*Which Agent Causes Task Failures and When? On Automated Failure Attribution of LLM Multi-Agent Systems*。arXiv。https://arxiv.org/abs/2505.00212 — 提出來自 127 個多代理人系統的失敗日誌資料集 Who&When，並比較三種找出負責代理人與步驟的方法。
- Qian, C. 等人（2023）。*ChatDev: Communicative Agents for Software Development*。arXiv。https://arxiv.org/abs/2307.07924 — 以具角色分工的代理人模擬軟體公司的多代理人框架，也是 MAST 分析其追蹤紀錄的系統之一。
- Wu, Q. 等人（2023）。*AutoGen: Enabling Next-Gen LLM Applications via Multi-Agent Conversation*。arXiv。https://arxiv.org/abs/2308.08155 — 以相互對話的代理人建構應用程式的開源框架；MAST 研究的是其後續版本 AG2。

# ToolLLM: Facilitating Large Language Models to Master 16000+ Real-world APIs

ToolLLM (Qin et al., 2023) is a framework for tool use in open language models. It provides a large instruction dataset over real REST APIs, a depth-first search that finds valid chains of calls, an automatic evaluator, and a model, ToolLLaMA, trained on the data. It is one of three method pages on the [Tool Calling and the Model Context Protocol](../index.md) page.

## Overview

Open models such as LLaMA were weak at tool use. The authors argue that instruction tuning had concentrated on language skills and ignored tool use, while closed models such as ChatGPT performed much better. ToolLLM tackles the problem as a whole: the data needed to teach tool use, the training of a model on that data, and a way of evaluating the result. The aim is to cover the many APIs that real applications use, not a handful of tools chosen for a benchmark.

## Key concepts

- **ToolBench**: the instruction dataset. The authors collected 16,464 RESTful APIs in 49 categories from RapidAPI Hub, generated instructions that use them, and annotated a solution path for each instruction.
- **Single-tool and multi-tool instructions**: requests that need one API, or several APIs from one category or collection.
- **Solution path**: the sequence of API calls, and the final answer, that completes an instruction.
- **Depth-first search decision tree (DFSDT)**: a search over reasoning steps in which the model may abandon a branch and try another.
- **ToolEval**: an automatic evaluator that reports a pass rate, whether an instruction was completed within budget, and a win rate, a comparison of two solution paths judged by ChatGPT.
- **API retriever**: a dense retriever that recommends relevant APIs from a large pool for each instruction.

## How it works

1. **Collect APIs.** Gather the RESTful APIs and their documentation, grouped by category.
2. **Generate instructions.** Prompt ChatGPT to write instructions that use one or several of the APIs.
3. **Annotate solution paths with DFSDT.** For each instruction, the search expands reasoning nodes, each a step that proposes an action. The model may call a "finish by giving up" function to abandon a node and expand a new one. The search prefers depth, and it keeps only paths that pass.
4. **Train ToolLLaMA.** Finetune LLaMA-2 7B on the instruction and solution-path pairs.
5. **Evaluate with ToolEval.** Score pass rate and win rate. The authors report that ChatGPT's judgements agree with human annotators 87.1 percent of the time on pass rate and 80.3 percent on win rate.

The authors frame DFSDT as a remedy for two weaknesses of simpler loops. An early mistake can propagate into a faulty loop, and a single path explores little of the action space.

## Results

The paper compares ReAct and DFSDT with ChatGPT on three instruction types. The average pass rate is 35.3 percent for ReAct and 63.8 percent for DFSDT. A baseline that runs ReAct repeatedly until it spends the same budget as DFSDT reaches 44.5 percent, so the gain is not only a matter of more attempts (Qin et al., 2023, Table 3).

In the main experiments, DFSDT improves the pass rate and win rate of every model tested, including ChatGPT, GPT-4, Claude-2 and Text-Davinci-003. ChatGPT with DFSDT surpasses GPT-4 with ReAct on pass rate. Vicuna and Alpaca pass no instructions. ToolLLaMA with DFSDT reaches a pass rate second only to GPT-4 with DFSDT, and it generalises to unseen instructions and tools. The abstract adds that it also transfers zero-shot to the APIBench dataset, and that it can be paired with a neural API retriever.[^1]

## Limitations

- **Teacher dependence.** The instructions and solution paths were generated by ChatGPT, so the student model inherits its teacher's blind spots.
- **Evaluator limits.** ToolEval agrees with human judgement often but not always, and it relies on ChatGPT as the judge.
- **Search cost.** DFSDT makes more model calls than ReAct. The authors compare against a budget-matched ReAct baseline, but in deployment the cost of a search grows with its tree.
- **Live services.** Pass rates depend on real APIs responding as documented, and such services change over time.
- **Oracle retrieval.** Most rows of the main table use the ground-truth API set. Only one row uses the trained retriever, so selection from a large pool is only partly tested.

## Open questions

- Does the search generalise beyond the tool-use tasks studied, as the authors suggest when they describe DFSDT as a general decision strategy?
- How much synthetic data from a stronger model is needed, and how much of its quality survives into a smaller student?
- Can search be made cheap enough for interactive use?

## References

### Seminal papers

- Qin, Y. et al. (2023). *ToolLLM: Facilitating Large Language Models to Master 16000+ Real-world APIs*. arXiv. https://arxiv.org/abs/2307.16789 — The paper described here, with the ToolBench dataset, DFSDT, ToolEval and ToolLLaMA.
- Yao, S. et al. (2022). *ReAct: Synergizing Reasoning and Acting in Language Models*. arXiv. https://arxiv.org/abs/2210.03629 — The reasoning-and-acting loop that DFSDT is compared against in the paper.
- Wei, J. et al. (2022). *Chain-of-Thought Prompting Elicits Reasoning in Large Language Models*. arXiv. https://arxiv.org/abs/2201.11903 — Introduces step-by-step reasoning in prompts, the single-path reasoning that the authors contrast with tree search.
- Shinn, N. et al. (2023). *Reflexion: Language Agents with Verbal Reinforcement Learning*. arXiv. https://arxiv.org/abs/2303.11366 — Agents that write verbal reflections after failed attempts, a related way of recovering from errors.
- Touvron, H. et al. (2023). *LLaMA: Open and Efficient Foundation Language Models*. arXiv. https://arxiv.org/abs/2302.13971 — Introduces the open base models that ToolLLaMA is finetuned from.

### Surveys and textbooks

- Qin, Y. et al. (2023). *Tool Learning with Foundation Models*. arXiv. https://arxiv.org/abs/2304.08354 — Framework for tool learning in which models decompose tasks, plan and select tools, and reviews the field with experiments.

[^1]: Qin et al. (2023), abstract and Table 4 of the ToolLLM paper, https://arxiv.org/abs/2307.16789 — Source of the zero-shot transfer to APIBench and the pass-rate ordering reported in the main experiments.

# Toolformer：語言模型能自學使用工具

Toolformer（Schick 等人，2023）訓練語言模型決定該呼叫哪一個工具、何時呼叫、以什麼引數呼叫，以及如何使用結果。它只需要每個工具的少量示範，因為模型會以自己提出的候選呼叫來標註文字語料。它是 [工具呼叫與 Model Context Protocol](../index.md)概述頁所列的三個方法頁之一。

## 概述

語言模型寫出的文字很流暢，但在某些事情上並不可靠，例如那些簡單程式就能精確完成的算術，或是訓練後才改變的事實。一種補救方式是採用固定的流程，把這類問題交給工具處理。Toolformer 則問：模型能否自己學會這套流程？作者的目標是避開大量由人工標註的工具使用語料。他們從一般的純文字集開始，讓模型在其中提出 API 呼叫，只保留那些有助於模型預測後續文字的呼叫。

這些工具包括計算機、一個問答系統、兩個搜尋引擎、一個翻譯系統與一本行事曆（Schick 等人，2023）。

## 關鍵概念

- **行內 API 呼叫**：以文字形式寫在訓練序列中的工具呼叫，包含工具名稱、引數，以及呼叫之後的結果。由於呼叫本身就是文字，同一個寫語言的模型也能寫出呼叫。
- **自我監督**：模型以每個工具的少量範例提示，為文字加上標註，因此標籤來自模型而非人類。
- **有用性篩選**：只有當加入某個候選呼叫及其結果後，能降低模型對後續詞元的損失時，該呼叫才會被保留。

## 運作方式

對於模型 $M$ 與文字 $x_1, \dots, x_n$，論文定義從位置 $i$ 開始、在前綴 $z$ 條件下的加權損失為

$$
L_i(z) = -\sum_{j=i}^{n} w_{j-i} \log p_M(x_j \mid z, x_{1:j-1}).
$$

在位置 $i$ 上，呼叫 $c_i$ 與其結果 $r_i$ 以兩種方式比較：$L_i^+ = L_i(e(c_i, r_i))$，即把呼叫與其結果放在文字之前的損失；$L_i^- = \min\big(L_i(\varepsilon), L_i(e(c_i, \varepsilon))\big)$，即「不呼叫」與「呼叫但無結果」兩者中較好的一個。當 $L_i^- - L_i^+ \ge \tau_f$ 時保留該呼叫。其中 $e(\cdot)$ 表示格式化呼叫的函式，$\varepsilon$ 為空序列。

整個流程分為四個步驟：

1. **取樣。** 對每段文字，在少量範例的提示之後，計算模型在位置 $i$ 開始呼叫的機率 $p_i$。保留 $p_i > \tau_s$ 的位置，數量至多 $k$ 個；在每個位置取樣至多 $m$ 個候選呼叫，並以結束標記收尾。
2. **執行。** 執行每個候選呼叫，記錄其結果 $r_i$。
3. **篩選。** 只保留通過上述有用性測試的呼叫。
4. **微調。** 把保留下來的呼叫與結果穿插進原始文字，並以一般的語言建模損失在擴充後的語料上微調模型。基礎模型為 GPT-J，參數量 67 億。

推論時，當模型寫出呼叫的開頭標記，周圍的軟體便執行工具、插入結果，然後讓模型繼續生成。

## 結果

論文採零樣本評估，提示中沒有範例，並使用較寬鬆、適合自由文字生成模型的比對規則。

- **算術。** 在 ASDiv、SVAMP 與 MAWPS 上，Toolformer 分別得到 40.4、29.4 與 44.0 分；GPT-3（1750 億參數）則為 14.0、10.0 與 19.8 分（表 4）。模型在 97.9% 的例子中呼叫計算機。停用工具時，Toolformer 得 14.8、6.3 與 15.0 分，仍高於其 GPT-J 基線；作者把這歸因於對呼叫範例的微調。
- **事實補全。** 在三個 LAMA 子集上，Toolformer 比同等規模的最佳基線分別高出 11.7、5.2 與 18.6 分，並可與 GPT-3（1750 億參數）相比（表 3）。它在 98.1% 的例子中使用問答工具。
- **問答。** 在 Web Questions 上，Toolformer 得 26.3 分，GPT-3（1750 億參數）為 29.0 分。它勝過同等規模的基線，但未達更大模型的水準（表 5）。[^1]

## 限制

- **無法串接呼叫。** 各工具的呼叫是獨立產生的，因此訓練資料中沒有一個工具的輸出餵給另一個工具的例子。作者把這點列為明確的限制。
- **無法互動使用。** 模型無法瀏覽搜尋結果列表，也無法修正自己的查詢。
- **對措辭敏感。** 是否進行呼叫，取決於輸入的確切措辭。
- **樣本效率低。** 作者報告，處理超過一百萬份文件，只產生數千個有用的計算機範例。
- **只允許一次呼叫。** 評估時每個輸入至多一次呼叫，以避免模型不斷呼叫工具、卻不產生任何輸出的迴圈。

## 開放問題

- 能否重複進行取樣與篩選的流程，以學會串接工具與互動使用？作者以類似自助法（bootstrapping）的方式，建議可以反覆迭代。
- 模型應如何權衡一次呼叫的好處與其成本？
- 論文測試的是五種工具，基礎模型為 67 億參數。當工具數量大幅增加、模型規模更大時，這套方法的表現如何，仍未經檢驗。

## 參考文獻

### 奠基性論文

- Schick, T. et al. (2023). *Toolformer: Language Models Can Teach Themselves to Use Tools*. arXiv. https://arxiv.org/abs/2302.04761 — 本頁所述的論文，提出以有用性篩選進行的自我監督工具使用。
- Brown, T. B. et al. (2020). *Language Models are Few-Shot Learners*. arXiv. https://arxiv.org/abs/2005.14165 — 提出 GPT-3 與少樣本提示，是 Toolformer 算術與問答結果所比較的基線模型。
- Yao, S. et al. (2022). *ReAct: Synergizing Reasoning and Acting in Language Models*. arXiv. https://arxiv.org/abs/2210.03629 — 以提示取代訓練的做法，模型在其中把推理與行動交錯進行，而非學會何時呼叫工具。
- Patil, S. G. et al. (2023). *Gorilla: Large Language Model Connected with Massive APIs*. arXiv. https://arxiv.org/abs/2305.15334 — 後續的 API 呼叫微調方法，在提示中加入檢索到的文件。

### 綜述與教科書

- Qu, C. et al. (2024). *Tool Learning with Large Language Models: A Survey*. arXiv. https://arxiv.org/abs/2405.17935 — 工具學習的綜述，依規劃、工具選擇、工具呼叫與回應生成來整理。

[^1]: Schick 等人（2023），Toolformer 論文的表 5，https://arxiv.org/abs/2302.04761 — Toolformer 與 GPT-3（1750 億參數）在 Web Questions 上的分數來源。

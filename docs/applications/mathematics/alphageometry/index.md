# AlphaGeometry (Trinh et al. 2024)

AlphaGeometry is a neuro-symbolic system that proves Euclidean plane geometry problems at olympiad level. A language model suggests auxiliary constructions, such as an extra point or line, and a symbolic deduction engine works out what follows from them. Trinh and colleagues reported the system in Nature in 2024. It is one of the three landmark methods described on the parent page [Mathematics and Formal Proof](../index.md).

## Overview

Many olympiad geometry problems need an auxiliary construction, a point or line the statement does not mention but that makes the proof visible. Choosing it is the hard step; the rest is largely routine deduction. Learned provers lacked training data here, since human proofs must be translated into machine-checkable form, which is especially hard for geometry (Trinh et al., 2024).

AlphaGeometry avoids human demonstrations. It generates millions of synthetic theorems and proofs, trains a language model on them, and uses the model only to propose constructions. The symbolic engine does the deduction, so every step stays checkable.

## Key concepts

- **Euclidean plane geometry**: points, lines, circles and angles, described in a small formal language of geometric predicates.
- **Deduction engine**: a symbolic component that applies geometric rules forward until no new facts follow.
- **Auxiliary construction**: a new point or line added to the figure. The language model proposes these.
- **Branching search**: each construction choice opens a new branch, so the search tree is very wide.
- **Synthetic data**: theorems generated by sampling figures and recording what the engine can derive.

## How it works

The system runs a loop of deduction and proposal:

1. Translate the problem into formal premises and a goal statement.
2. Run the deduction engine to derive all consequences of the premises. Stop if the goal appears.
3. Otherwise, ask the language model for several candidate auxiliary constructions, conditioned on the current state.
4. Add each candidate to the figure and return to step 2, keeping a search over the branches.
5. When the goal is reached, output the proof. Trinh et al. report that the proofs are human-readable.

The language model is the only learned component. Its suggestions are never trusted by themselves: a construction is useful only if the engine can derive the goal from it.

## Results

On 30 recent olympiad-level geometry problems, AlphaGeometry solved 25, against ten for the previous best method. The authors describe this as approaching an average IMO gold medallist (Trinh et al., 2024). Under expert evaluation it solved all the geometry problems of IMO 2000 and 2015. The abstract gives these counts; this page quotes no further figures.

## Limitations

- **Scope.** The system handles Euclidean plane geometry only. Its formal language did not cover every problem type: the successor system reports that coverage of IMO 2000 to 2024 geometry problems rose from 66% to 88% when the language was extended (Chervonyi et al., 2025).
- **Translation.** Problems must be turned into the formal language before the system can work. Translating natural-language statements faithfully is the difficulty that autoformalisation studies address (Wu et al., 2022). The successor system is described as progress towards a fully automated pipeline from natural language, not a finished one (Chervonyi et al., 2025).
- **Synthetic data.** Training depends on a generator of theorems the engine can solve, which is hard to reproduce outside geometry.
- **Search cost.** The search tree is wide, so a single problem can need substantial computation.

## Open questions

- Can the split between a language model and a symbolic engine be extended beyond geometry, into algebra and number theory, where the formal languages are different? [AlphaProof](../alphaproof/index.md) takes a different route, using Lean.
- Does the language model learn anything reusable about geometric intuition, or mainly the statistics of the synthetic data? Yang et al. (2024) argue that formal checking gives the automatic feedback needed to measure real progress.
- How much of the performance comes from the engine and how much from the learned proposals? Petrov et al. (2025) grade full proofs by hand, which shows how costly it is to judge proof quality without a checker.

## Connections

- The deduction engine is a classical [symbolic AI](../../../theory/paradigms/symbolic-ai/index.md) component, combined here with a learned proposal model, a pattern that recurs across this field.
- AlphaGeometry 2 was combined with AlphaProof to reach silver-medal standard at IMO 2024 (Hubert et al., 2025).
- Human geometers draw auxiliary lines by eye, linking the task to spatial vision, covered on the [visual perception](../../../brain-mind/visual-perception/index.md) page.

## Applications

The system served as a component of the IMO 2024 silver-medal-equivalent entry (Hubert et al., 2025), and its successor is the basis for work on a fully automated geometry pipeline (Chervonyi et al., 2025).

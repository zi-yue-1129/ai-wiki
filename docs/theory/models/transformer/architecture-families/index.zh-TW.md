# 編碼器、解碼器與編碼器–解碼器 Transformer

[Transformer](../index.md) 可以用三種形式使用。編碼器專用（encoder-only）模型一次讀入整段輸入；解碼器專用（decoder-only）模型根據前面的 token 預測每個 token；編碼器–解碼器（encoder-decoder）模型則用一個堆疊讀入輸入，再用第二個堆疊產生輸出，並關注第一個堆疊的結果。模型的形式決定哪一種預訓練目標最合適，以及模型擅長哪些任務。BERT、GPT 與 T5 是三個代表性的例子。

## 概述

[Vaswani 等人（2017）](../attention-is-all-you-need/index.md)提出的原始 Transformer 是一個用於機器翻譯的編碼器–解碼器。之後的工作各保留了其中一半。BERT 保留編碼器，並訓練它填補被遮蓋的詞，這適合理解類任務。GPT 系列保留解碼器，並訓練它預測下一個 token，這適合生成類任務。T5 兩半都保留，並把每個任務都框架為文字到文字，使同一個模型能用於許多任務。

三種形式的差異在於每個位置可以關注哪些位置。這個選擇是主要的設計決策，也決定了哪些預訓練目標是自然的。

## 關鍵概念

- **雙向注意力**：每個位置都能關注所有其他位置，包括前後兩個方向。編碼器使用它。
- **因果注意力**：每個位置只能關注較早的位置。解碼器使用它，使生成與訓練保持一致。
- **交叉注意力**：解碼器的位置關注編碼器的輸出。只有編碼器–解碼器模型具有它。
- **預訓練目標**：在未標註文字上訓練所用的任務，例如遮蓋 token 預測或下一個 token 預測。

## 運作方式

| 形式 | 注意力 | 預訓練目標 | 典型用途 | 代表性例子 |
|---|---|---|---|---|
| 編碼器專用 | 雙向 | 遮蓋 token 預測 | 分類、抽取、嵌入表示 | [BERT](bert/index.md) |
| 解碼器專用 | 因果 | 下一個 token 預測 | 開放式生成、對話、少樣本提示 | [GPT-3](../../llm/gpt-3-few-shot/index.md) |
| 編碼器–解碼器 | 雙向編碼器，加上具交叉注意力的因果解碼器 | 跨度破壞（span corruption）或其他序列到序列目標 | 翻譯、摘要、問答 | [T5](t5/index.md) |

三者在程式碼上的差別就在遮罩。編碼器讓每個 token 都能關注所有其他 token。解碼器加上因果遮罩，使位置 \(t\) 的 logits 只依賴 \(1, \dots, t\) 的 token。如此一來，解碼器可以在一次前向傳播中對每個位置進行訓練，並以下一個 token 作為目標。

## 關鍵方法

每個方法都有自己的頁面。這裡的概覽是簡要的。

### BERT（Devlin 等人，2019）

- **概述：** 編碼器以同時來自左右兩側的上下文預測被遮蓋的 token 進行預訓練，然後為每個任務加上一個輸出層進行微調。
- **比較：** 編碼器專用家族。它的雙向上下文適合需要讀取整段輸入的任務，但無法像解碼器那樣從左到右生成文字。
- **完整內容：** [BERT](bert/index.md)

### T5（Raffel 等人，2020）

- **概述：** 以跨度破壞目標預訓練的編碼器–解碼器，並以同一種文字到文字格式在每個任務上微調。
- **比較：** 保留 Transformer 的兩半。它為許多任務提供單一介面，代價是要運行兩個堆疊。
- **完整內容：** [T5](t5/index.md)

### GPT（解碼器專用）

- **概述：** 在大型文字語料上訓練以預測下一個 token 的解碼器。擴大規模後，僅靠提示即可達到少樣本表現。
- **比較：** 解碼器專用家族。它的因果目標與生成直接吻合。GPT-3 頁面涵蓋規模化的證據與少樣本結果。
- **完整內容：** [GPT-3：語言模型是少樣本學習者](../../llm/gpt-3-few-shot/index.md)

## 為什麼解碼器專用模型主導 LLM

目前大多數使用中的大型語言模型都是解碼器專用的。以下理由是常見的解釋，並非已定論的結果。下一個 token 的目標與生成相同，因此訓練訊號與使用情境一致。單一解碼器堆疊也能把任何任務當作提示的延續來處理，不需要針對任務的額外輸出頭。[GPT-3 頁面](../../llm/gpt-3-few-shot/index.md)說明了在這種設定下少樣本表現隨規模增長的證據。這種優勢是否適用於所有任務，仍有討論。

## 應用

- 編碼器專用模型用於搜尋排序、文字分類與命名實體辨識。
- 解碼器專用模型用於對話助理、程式碼生成與開放式寫作。
- 編碼器–解碼器模型用於翻譯與摘要。

## 開放問題

- 單一解碼器專用模型，能否在需要一次看完整段輸入的任務（例如資料很少的分類）上，追上雙向編碼器。
- 編碼器–解碼器模型在輸入與輸出界線清楚的任務中，是否有持續的優勢。
- 解碼器專用模型的優勢有多少來自規模，有多少來自目標本身。
